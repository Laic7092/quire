# 架构与运行时不变式

这份文档记录窗口、排版、绘画和后台任务之间的所有权。改动某一层之前先看这里；功能说明
仍以 README 和各包的 package comment 为准。

## 分层

| 层 | 负责 | 不负责 |
| --- | --- | --- |
| 根包窗口层 | MyGo 窗口、场景、菜单、输入、动画、排版调度 | EPUB 解析、全文索引实现、书源协议 |
| `internal/reader` | 字体、`render.Layout` 构建、`UIPainter`、字形图集、选区几何 | 窗口和持久化 |
| `internal/appstate` | 面板状态、搜索/目录/书签/笔记的接线、惰性索引入口 | 创建窗口或 goroutine 调度 |
| `internal/book` / `internal/library` | 书籍打开与书架元数据 | 排版与 UI |
| `internal/store` | 书架、位置、批注、偏好 | 窗口状态 |
| `internal/source*` | 搜索、下载、书源配置 | 在线阅读和 UI |

## 窗口所有权

- `desk` 持有跨窗口的只读/共享服务：store、字体、书源、主题、阅读目标与菜单。
- 一个 `app` 只代表一扇窗口。页码、滚动、选区、排版任务、面板和任务作用域都属于它。
- 所有 UI 状态只在 UI 线程写。后台任务只能读取启动时复制的输入，结果统一经
  `app.post` / `Window.Update` 回 UI 线程。
- `taskScope` 绑定窗口生命周期；窗口关闭时 `closeTasks` 取消所有任务，取消之后到达的
  callback 直接丢弃。
- 后台代码不调用 `showWindow` 或创建窗口；窗口不存在时结果丢弃。

## 排版状态

`ensureLayout` 先经过纯函数 `chooseLayoutGate`：

1. 阅读区域太小；
2. 首帧尚未测量；
3. 书或字体未就绪；
4. 同一请求已经失败；
5. 同一请求已有任务在跑；
6. 已发布布局正是当前请求；
7. 需要预览、重绘或整本重排。

预览、整本重排和失败恢复仍由 `app` 执行，但守卫条件不再散落在方法里。窗口 resize
的两段式策略（当前章预览 → 静默期后整本重排）保持不变。

## 调色板

生产路径必须使用窗口捕获的 `app.pagePal`：

- `applyTheme` 每帧更新它，并同步 `UIPainter` 的 palette；
- 排版、重排、范围重排、重绘、封面、选区、搜索高亮、滚动标记和 PNG 导出都显式传入；
- `reader.Current()` / `SetPalette()` 只保留为旧调用方和手写测试的兼容入口，不再决定
  新窗口的页面颜色。

这样同一进程内不同窗口不会因为一次全局写入而用错纸色，测试也不依赖执行顺序。

## 搜索索引

全文索引是文档级缓存，不是布局的一部分：

- 构建文档时只安装 `appstate.SetIndexBuilder`，不遍历整本书；
- 第一次搜索才在后台构建索引；
- 同一文档只构建一次；
- 换书、换字号或重建文档时取消旧构建；已完成的活动查询会在新索引上重跑；
- 取消的构建不能把结果发布到新书或新文档。

## 缓存与构建

- 封面缓存上限 `coverCacheLimit = 128`，按 UI 线程内的 LRU 顺序淘汰。
- `go.mod` 的 layx replace 使用相对路径；仓库需要和 layx 检出并排。开发 worktree 可用
  `go.work` 或同级的 `layx` symlink，不要提交绝对路径。
